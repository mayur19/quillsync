# Glossary

Domain terms used across quillsync's code and documentation. Where a term maps to code, the module path is given. Requirement IDs refer to [product/requirements.md](product/requirements.md).

## CRDT and data model

| Term                                          | Definition                                                                                                                                                                                                                                                                             |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CRDT (Conflict-free Replicated Data Type)** | A data structure that replicas can update independently and concurrently. Any two replicas that have received the same set of updates reach the same state without coordination. quillsync uses an operation-based sequence CRDT (`packages/shared/src/crdt`).                         |
| **Sequence CRDT**                             | A CRDT for an ordered list, here the characters of a document. It supports insert-at-position and delete.                                                                                                                                                                              |
| **RGA (Replicated Growable Array)**           | The sequence CRDT algorithm quillsync implements. Each inserted element gets a unique ID and is placed after its _origin_. Concurrent inserts at the same origin are ordered by descending (lamport, client). Deleted elements become _tombstones_.                                    |
| **Replica**                                   | One copy of a document's CRDT state. Every editor tab is a replica, and so is the server's in-memory room.                                                                                                                                                                             |
| **Client ID**                                 | A random string identifying one replica, created per editor tab on load. It is part of every item ID and of the ordering tiebreak.                                                                                                                                                     |
| **Item**                                      | One element of the sequence: a single character code point together with its ID, Lamport timestamp, origin and deleted flag (`packages/shared/src/crdt/types.ts`).                                                                                                                     |
| **ItemId**                                    | The unique identifier of an item: `{client, seq}`.                                                                                                                                                                                                                                     |
| **seq**                                       | A per-client counter assigned to each op. It is contiguous (1, 2, 3, …), which lets a state vector summarize everything received from that client with one number.                                                                                                                     |
| **Lamport timestamp**                         | A logical clock value. On each local op it is set to one more than the highest timestamp the replica has seen. Together with the client ID it gives a total order (lamport, client) that is consistent with causality. It never depends on wall-clock time (NFR-004).                  |
| **Origin**                                    | For an insert, the ItemId of the nearest _visible_ item to its left at creation time, or `null` for the start of the document. Integration places the new item after its origin.                                                                                                       |
| **Integration**                               | Applying a remote op to local state. For an insert: start immediately after the origin, skip every item whose (lamport, client) is greater than the new item's, and insert there. The cost is O(n) per op (`integrate.ts`).                                                            |
| **Timestamp tree**                            | An equivalent view of RGA. Each item's parent is its origin, and children are sorted by descending (lamport, client). A pre-order traversal gives document order. Used for O(n log n) batch merge and rehydration (`materialize.ts`, FR-021).                                          |
| **Materialization**                           | Producing the visible text, or the full ordered item list, from CRDT state.                                                                                                                                                                                                            |
| **Tombstone**                                 | A deleted item that is kept in the sequence and flagged `deleted`, so that later ops that reference it as origin or target still integrate correctly.                                                                                                                                  |
| **Op (operation)**                            | A unit of change sent between replicas. `insert {id, lamport, origin, char}` or `delete {id, lamport, target}`.                                                                                                                                                                        |
| **Run**                                       | A compressed group of ops. Consecutive inserts by one client with consecutive seq and Lamport values, where each character's origin is the previous character, become `{client, seq, lamport, origin, text}`. Consecutive deletes become a run with target ranges (`runs.ts`, FR-022). |
| **Codec**                                     | The binary encoding of runs for the wire and for storage. It uses LEB128 varints, a client-ID dictionary and UTF-8 text, and malformed input throws `CodecError` (`codec.ts`, NFR-005).                                                                                                |
| **LEB128 varint**                             | A variable-length integer encoding that stores 7 bits per byte. Small numbers take one byte.                                                                                                                                                                                           |
| **State vector**                              | A map from client ID to the highest contiguous seq received from that client. It summarizes a replica's knowledge compactly and is exchanged in `hello` and `welcome`.                                                                                                                 |
| **Delta sync**                                | Sending a peer only the ops it lacks: every op with `seq > remoteVector[client]`.                                                                                                                                                                                                      |
| **Causal readiness**                          | An op is ready when `seq == vector[client] + 1` and its dependency (an insert's origin, or a delete's target) is present.                                                                                                                                                              |
| **Pending buffer**                            | The per-replica holding area for ops that arrived before they were causally ready. They are integrated as soon as their dependencies arrive (`document.ts`, FR-020).                                                                                                                   |
| **Idempotent delivery**                       | Receiving an op more than once has the same effect as receiving it once. Ops with `seq <= vector[client]` are dropped (NFR-003).                                                                                                                                                       |
| **Convergence**                               | The guarantee that replicas which have integrated the same set of ops are identical, whatever the order in which they received them (NFR-001).                                                                                                                                         |
| **Intention preservation (non-interleaving)** | Runs typed concurrently at the same position stay contiguous rather than mixing character by character (NFR-002).                                                                                                                                                                      |
| **Interleaving anomaly**                      | The failure mode that intention preservation prevents: two users' concurrently typed words mixed together, such as "hweolrllod".                                                                                                                                                       |
| **Causal stability**                          | An op is causally stable when every known replica has acknowledged it. No future op can then be concurrent with it.                                                                                                                                                                    |
| **Stable vector (GC frontier)**               | The pointwise minimum of all tracked replicas' acknowledged state vectors. Ops covered by it are causally stable.                                                                                                                                                                      |
| **Garbage collection (GC)**                   | Removing tombstones that are no longer needed. quillsync collects a tombstone only if its delete is causally stable _and_ no retained item uses it as origin, which is a single right-to-left O(n) pass (`gc.ts`, FR-023 library and FR-052 server wiring).                            |
| **Retained child**                            | An item whose origin is a given tombstone. While one exists, the tombstone cannot be collected, because removing it would change where future concurrent inserts integrate.                                                                                                            |
| **Anchor**                                    | A position stored as the ItemId of the character to its left, or `null`. It stays correct under concurrent edits and still resolves when that character is tombstoned. Used for carets and comment ranges (`anchors.ts`, FR-024).                                                      |
| **Mark**                                      | A formatting attribute (bold, italic, code, link) applied to a range of items (planned, FR-025).                                                                                                                                                                                       |
| **Block**                                     | A structural unit of a document (paragraph, heading, list item, quote, code block, table, image) represented on the sequence CRDT (planned, FR-026).                                                                                                                                   |
| **Text diff**                                 | Converting a textarea change into ops by finding the common prefix and suffix, which gives at most one delete run and one insert run (`packages/shared/src/text/diff.ts`).                                                                                                             |

## Sync and collaboration

| Term                      | Definition                                                                                                                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Room**                  | The server-side, in-memory, per-document collaboration hub. It holds the CRDT state, the connected sockets and presence. A room serializes integrate, persist, acknowledge and broadcast on a per-room promise queue (`apps/api/src/modules/collab/room.ts`). |
| **Room registry**         | The process-wide map from document ID to room. It loads (rehydrates) a room on first join and unloads it when the last socket leaves (`room-registry.ts`).                                                                                                    |
| **Rehydration**           | Rebuilding a room's CRDT state from storage. Today this means decoding every `document_ops` row. With FR-050 it will mean loading the latest snapshot plus the op-log tail.                                                                                   |
| **Fan-out**               | Sending newly integrated ops from the room to every other socket in it (FR-034). Multi-node fan-out through Postgres LISTEN/NOTIFY is planned (FR-045).                                                                                                       |
| **Ack (acknowledgement)** | The server's `ack {vector}` message, sent to the originating client after its ops are durably persisted (NFR-011).                                                                                                                                            |
| **hello / welcome**       | The sync handshake. The client sends its client ID, state vector and display name. The server replies with its vector, the runs the client is missing, and the current peers.                                                                                 |
| **Outbound queue**        | The client-side list of local ops not yet acknowledged by the server. It is resent on reconnect (FR-041) and will be persisted to IndexedDB in FR-085.                                                                                                        |
| **Backoff**               | Reconnect delay that grows exponentially from 0.5 s to 10 s, with random jitter so that clients do not reconnect in lockstep.                                                                                                                                 |
| **Presence**              | Ephemeral, non-persisted information about who is in a document: display name, colour derived from the client ID, and caret anchor (FR-037).                                                                                                                  |
| **Awareness**             | Extended presence: selection ranges, idle state and follow mode (planned, FR-043).                                                                                                                                                                            |
| **Remote caret**          | The rendered cursor of another participant, positioned by resolving their anchor.                                                                                                                                                                             |
| **Peer**                  | Another participant connected to the same room.                                                                                                                                                                                                               |
| **Backpressure**          | Slowing or disconnecting a socket whose outbound buffer or op rate exceeds limits (planned, FR-044, NFR-035).                                                                                                                                                 |
| **Room ownership**        | In multi-node operation, the single node that holds a Postgres advisory lock for a document and integrates its ops (planned, FR-046).                                                                                                                         |

## Persistence and history

| Term                                 | Definition                                                                                                                                                                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Op log**                           | The append-only table `document_ops`. One row per persisted batch, holding a binary `payload`, `client_id`, `seq_start`, `seq_end` and `op_count`, and unique on (document, client, `seq_start`). Its `id` column gives the server order. |
| **Snapshot**                         | A persisted, encoded copy of a document's full CRDT state at a known state vector and op-log high-water ID (planned `document_snapshots`, FR-050).                                                                                        |
| **Compaction**                       | Deleting op-log rows that are fully covered by the latest snapshot and no longer needed by versions or lagging replicas (planned, FR-051).                                                                                                |
| **High-water mark**                  | The largest `document_ops.id` included in a snapshot.                                                                                                                                                                                     |
| **Replica acknowledgement tracking** | Persisting each client's last acknowledged vector (`document_replicas`) so the server can compute the GC frontier (planned, FR-052).                                                                                                      |
| **Replica eviction**                 | Dropping a long-silent replica from the GC frontier. If it returns, it must resync from a snapshot (planned, FR-053).                                                                                                                     |
| **Checkpoint**                       | An automatic version marker recorded periodically or when editing pauses (planned, FR-055).                                                                                                                                               |
| **Named version**                    | A checkpoint with a user-given name (planned, FR-056).                                                                                                                                                                                    |
| **Restore as forward ops**           | Restoring a past version by emitting new delete and insert ops that move the current state to the old text, rather than rewinding history. This keeps all replicas converging (planned, FR-058).                                          |
| **Outbox**                           | The `outbox_messages` table, where invitations, password resets and digests are written instead of being sent by email. quillsync uses no third-party email service (NFR-022).                                                            |

## Access and workspace

| Term                         | Definition                                                                                                                                                                                                                        |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Organization (workspace)** | The tenant boundary. Every document, membership and audit event belongs to exactly one organization.                                                                                                                              |
| **Membership**               | A user's role in an organization: `owner`, `editor`, `commenter` or `viewer`.                                                                                                                                                     |
| **Permission**               | A capability string checked by routes: `document:read`, `document:create`, `document:edit`, `document:comment`, `document:manage`, `member:manage`, `audit:read`, `workspace:manage` (`packages/shared/src/rbac/permissions.ts`). |
| **RBAC matrix**              | The fixed mapping from role to permissions (FR-011).                                                                                                                                                                              |
| **Effective role**           | The highest role from the organization membership plus document or folder grants (planned, FR-070).                                                                                                                               |
| **Share link**               | A revocable, expiring token that grants a role on one document (planned, FR-071).                                                                                                                                                 |
| **Session**                  | A server-side login record. The browser holds a random token in the `qs_session` cookie, and the database stores only an HMAC-SHA256 of it (keyed by `SESSION_SECRET`).                                                           |
| **CSRF double-submit**       | Protection in which state-changing requests must echo the `qs_csrf` cookie value in the `x-csrf-token` header (FR-009).                                                                                                           |
| **Audit log**                | The append-only record of security-relevant actions, with actor, target and request ID (FR-012).                                                                                                                                  |
| **Envelope**                 | The standard JSON response shape `{data, error, meta?}` (FR-002).                                                                                                                                                                 |
| **Pending endpoint**         | A registered route that returns `501 NOT_IMPLEMENTED` with the backlog ticket ID until its feature is built (FR-006).                                                                                                             |

## Planning

| Term                          | Definition                                                                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Epic (E0 to E11)**          | A thematic group of backlog tickets, such as E2 CRDT core.                                                                             |
| **Milestone (M0 to M9)**      | A time-boxed delivery increment with exit criteria (see [planning/roadmap.md](planning/roadmap.md)).                                   |
| **Ticket (QS-xxx)**           | A backlog item with an hour estimate, a status and dependencies (see [planning/backlog.md](planning/backlog.md)).                      |
